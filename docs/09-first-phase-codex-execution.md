# Ant Design Pro 大型 SaaS 系统第一阶段详细任务拆解与 Codex 执行提示词总文档

## 1. 文档定位

本文件用于指导 Codex 和开发团队执行大型 SaaS 系统第一阶段建设工作。

它不是重复前面的技术方案，而是把“该怎么做”进一步落到“先做什么、做到什么程度、哪些不能碰、完成后怎么验收”。

## 2. 第一阶段总目标

第一阶段必须完成一套可运行、可扩展、可验证的大型 SaaS 平台底座，至少具备：

- 前端统一主布局、统一页面模板、统一权限接入、统一请求封装、统一响应式策略、租户切换能力。
- 后端认证体系、多租户上下文、RBAC 权限骨架、统一接口规范、统一错误码、统一异常处理、统一审计日志、基础缓存封装、文件上传入口、异步任务骨架。
- 数据库租户、用户、组织、角色、菜单、字典、配置、日志、文件、任务等底座表结构。
- 本地开发可运行能力和测试环境可部署能力。

第一阶段不追求业务模块数量，追求底座能力做对、做稳、做统一。

## 3. 执行总原则

- 优先建设底座能力，不允许绕开统一规范直接堆页面。
- 所有前端页面必须从统一模板生长。
- 所有后端接口必须遵循统一响应结构、统一分页结构和统一错误码体系。
- 多租户能力必须是平台级能力，不允许通过手写 `tenant_id` 条件临时实现。
- 权限必须前后端同时接入。
- 日志、审计、缓存、文件、任务这些平台能力必须从第一阶段就预留正式接入方式。
- 所有实现都要优先考虑后续可复制扩展。

## 4. 第一阶段任务分组

建议拆成九个任务组：

1. 工程初始化与基础骨架
2. 数据库与后端基础设施初始化
3. 认证与租户上下文
4. 权限模型与菜单快照
5. 前端主壳层与基础模板
6. 系统管理最小功能闭环
7. 日志、审计、缓存、文件、任务骨架
8. 响应式适配与多端基础策略
9. 联调、自测、文档与部署

## 5. 任务组一：工程初始化与基础骨架

### 5.1 目标

建立前后端标准工程骨架，使项目具备统一目录、统一配置、统一运行方式和统一基础依赖。

### 5.2 前端任务

- 初始化 `React 18 + TypeScript + Umi Max + Ant Design Pro` 项目。
- 建立标准目录结构，包括 `layouts`、`pages`、`components`、`services`、`auth`、`tenant`、`responsive`、`cache`、`hooks`、`types`、`constants`、`utils`。
- 配置全局样式入口、主题入口和运行时配置入口。
- 建立统一请求封装文件与基础错误拦截骨架。
- 建立基础路由结构和基础异常页。

### 5.3 后端任务

- 初始化 `Spring Boot 3 + Java 21` 项目。
- 建立模块化目录结构，包括 `common`、`infrastructure`、`modules`。
- 接入 `MyBatis Plus`、`Spring Security`、`Redis`、`MySQL`。
- 建立统一返回体、统一错误码枚举、统一异常处理器、统一基础日志上下文。
- 集成数据库迁移工具。

### 5.4 验收标准

- 前后端项目都能独立启动。
- 目录结构符合规范。
- 基础依赖可正常加载。
- 后端存在统一 API 返回结构。
- 前端存在统一请求封装入口。

### 5.5 Codex 执行提示词

请基于大型 SaaS 系统脚手架要求，初始化前端与后端工程骨架。前端使用 `React 18`、`TypeScript`、`Umi Max`、`Ant Design Pro`，建立标准目录结构与统一请求入口；后端使用 `Spring Boot 3`、`Java 21`、`MyBatis Plus`、`Spring Security`、`Redis`、`MySQL`，建立模块化目录结构、统一返回结构、统一异常处理、统一错误码与数据库迁移机制。不要开始实现业务页面，只完成工程底座和基础运行能力。

## 6. 任务组二：数据库与后端基础设施初始化

### 6.1 目标

落地第一阶段底座数据库表结构与后端基础设施封装，为认证、租户、权限、系统管理页面提供支撑。

### 6.2 需要落地的基础表

- 租户表、租户套餐表、租户域名表、租户配额表
- 用户表、用户租户关联表、用户租户资料表
- 部门表、岗位表
- 角色表、菜单表、用户角色关联表、角色菜单关联表、数据范围规则表
- 字典类型表、字典项表、配置表
- 文件对象表、任务表、操作审计日志表、登录日志表

### 6.3 基础设施任务

- 完成 Redis 基础封装。
- 完成租户上下文容器骨架。
- 完成 traceId 注入。
- 完成统一分页对象与分页结果结构。
- 完成审计字段自动填充骨架。

### 6.4 验收标准

- 数据库初始化脚本可执行。
- 所有核心底座表可以正常建表。
- 后端存在统一分页模型。
- 日志上下文可输出 traceId。
- Redis 可正常连接并进行基础读写测试。

### 6.5 Codex 执行提示词

请按照大型 SaaS 系统数据库规范，为第一阶段落地核心底座表结构，并完成相应的实体、DTO、VO、Mapper 与基础 Repository 封装。接入 Redis 基础组件、分页结构、traceId 上下文、审计字段自动填充能力。不要开始做复杂业务逻辑，优先完成可供后续模块复用的底层数据与基础设施能力。

## 7. 任务组三：认证与租户上下文

### 7.1 目标

完成登录、登出、刷新 token、当前用户、当前租户、可访问租户列表、租户切换等能力，建立完整租户上下文。

### 7.2 后端任务

- 实现登录接口。
- 实现登出接口。
- 实现刷新 token 接口。
- 实现获取当前用户接口。
- 实现获取当前租户接口。
- 实现获取用户可访问租户列表接口。
- 实现租户切换接口。
- 完成 Redis 会话存储。
- 完成登录日志记录。

### 7.3 前端任务

- 实现登录页。
- 实现登录态恢复逻辑。
- 实现未登录跳转。
- 实现当前租户展示。
- 实现租户切换组件。
- 实现登录后初始化用户信息与权限快照加载流程。

### 7.4 关键约束

- 租户切换不能只是切换前端本地状态，必须调用后端接口并刷新上下文。
- 一个用户可以属于多个租户。
- 切换租户后必须重载权限与菜单。

### 7.5 验收标准

- 用户可以登录系统。
- 登录后可获取可访问租户列表。
- 可切换租户。
- 切换租户后当前上下文变化生效。
- 登录和切换行为都有日志记录。

### 7.6 Codex 执行提示词

请实现第一阶段认证与租户上下文闭环。后端完成登录、登出、刷新 token、当前用户、当前租户、可访问租户列表、租户切换接口，并基于 Redis 维护会话状态和登录日志。前端完成登录页、登录态恢复、当前租户展示与租户切换组件。要求租户切换后必须刷新当前上下文，不允许仅通过前端本地缓存模拟切换。

## 8. 任务组四：权限模型与菜单快照

### 8.1 目标

完成 RBAC 权限骨架、权限快照、菜单树和按钮权限统一接入。

### 8.2 后端任务

- 实现角色表、菜单表、用户角色关联、角色菜单关联的基础服务。
- 实现权限快照生成逻辑。
- 实现菜单树查询接口。
- 实现统一 `permission_key` 模型。
- 实现接口级权限注解骨架。
- 预留数据范围规则结构。

### 8.3 前端任务

- 基于权限快照动态生成菜单。
- 实现页面访问控制。
- 实现 `PermissionButton` 组件。
- 实现菜单随租户切换自动刷新。
- 实现无权限页面。

### 8.4 关键约束

- 前端菜单显隐不能代替后端鉴权。
- 所有按钮权限统一使用 `permission_key`，不允许每页自定义字符串。
- 菜单、按钮、接口权限标识要统一。

### 8.5 验收标准

- 登录后菜单根据权限变化。
- 按钮根据权限变化。
- 后端接口存在基础权限拦截能力。
- 租户切换后菜单与按钮权限重新计算。

### 8.6 Codex 执行提示词

请实现大型 SaaS 第一阶段权限骨架。后端完成角色、菜单、用户角色、角色菜单、权限快照、菜单树和基础接口鉴权能力；前端基于权限快照完成动态菜单、页面访问控制、`PermissionButton` 组件和无权限页。所有权限统一采用 `permission_key`，不允许出现多套权限标识体系。

## 9. 任务组五：前端主壳层与基础模板

### 9.1 目标

建立统一主布局、统一页面骨架和统一高频组件，为后续页面快速复制提供模板。

### 9.2 必做组件与骨架

- `BasicLayout`
- `UserLayout`
- `BlankLayout`
- `TenantSelector`
- `QueryPanel`
- `ActionBar`
- `DataTable`
- `DetailDrawer`
- `PermissionButton`
- `EmptyState`
- 统一列表页模板
- 统一表单页模板
- 统一详情页模板

### 9.3 关键约束

- 整个页面尽量不全局滚动，只让核心内容区滚动。
- 查询区、操作区、表格区、详情区结构必须统一。
- 弹窗和抽屉使用规则要统一。

### 9.4 验收标准

- 至少有一类标准列表页模板可复用。
- 布局中已集成租户切换、用户菜单、通知入口占位。
- 页面结构符合统一规范。
- 新增一个标准管理页时不需要重写布局容器。

### 9.5 Codex 执行提示词

请实现大型 SaaS 管理端前端主壳层与基础页面模板。基于 Ant Design Pro 建立 `BasicLayout`、`UserLayout`、`BlankLayout`，并实现 `QueryPanel`、`ActionBar`、`DataTable`、`DetailDrawer`、`PermissionButton` 等通用组件。要求统一列表页、表单页、详情页结构，尽量让表格区成为主要滚动区域，避免整个页面滚动。不要写成零散页面集合，而要写成可复用模板体系。

## 10. 任务组六：系统管理最小功能闭环

### 10.1 目标

通过系统管理模块验证整套底座是否真正可用。

### 10.2 必做模块

- 用户管理
- 角色管理
- 菜单管理
- 部门管理
- 字典管理
- 配置管理
- 登录日志
- 操作日志

### 10.3 每个模块最低要求

- 列表页
- 新增/编辑
- 详情查看或抽屉查看
- 状态切换
- 权限控制
- 分页查询
- 统一响应结构
- 租户隔离
- 审计记录

### 10.4 验收标准

- 用户管理可完成新增、编辑、状态切换。
- 角色管理可完成菜单授权。
- 菜单管理支持树结构。
- 字典与配置可正常读取与修改。
- 日志页可查询登录日志和操作日志。
- 整套系统前后端交互风格已统一。

### 10.5 Codex 执行提示词

请在已完成的底座之上，优先实现系统管理第一批最小闭环模块：用户管理、角色管理、菜单管理、部门管理、字典管理、配置管理、登录日志、操作日志。要求所有页面都使用统一模板，所有接口都遵循统一响应结构，所有模块都纳入租户上下文和权限控制，关键写操作必须记录审计日志。目标是验证整套底座是否真正跑通，而不是只把页面做出来。

## 11. 任务组七：日志、审计、缓存、文件、任务骨架

### 11.1 目标

接入第一阶段必须存在的平台能力入口，但不追求一次做满。

### 11.2 日志与审计

- 统一 traceId。
- 统一操作日志记录。
- 统一登录日志记录。
- 关键接口审计切面或拦截器。

### 11.3 缓存

- 字典缓存。
- 配置缓存。
- 权限快照缓存。
- 租户切换后缓存刷新机制。

### 11.4 文件

- 统一上传接口。
- `file_object` 元数据落库。
- 基本文件类型和大小校验。

### 11.5 任务

- `task_job` 表。
- 任务查询接口。
- 任务详情接口。
- 导入导出任务骨架预留。

### 11.6 验收标准

- 关键请求有 traceId。
- 关键写操作能在审计日志看到。
- 字典和配置具备基本缓存。
- 文件上传可用且元数据可查。
- 任务表和任务接口存在。

### 11.7 Codex 执行提示词

请为大型 SaaS 第一阶段补齐日志、审计、缓存、文件、任务的基础能力骨架。要求接入 `traceId`、操作日志、登录日志、字典与配置缓存、统一文件上传和 `file_object` 元数据记录，以及 `task_job` 表和基础任务查询接口。不要急于实现完整导入导出中心，但必须为后续任务化能力预留标准入口。

## 12. 任务组八：响应式适配与多端基础策略

### 12.1 目标

完成桌面端为主、平板可用、移动端关键能力可访问的基础适配。

### 12.2 前端任务

- 建立统一断点体系。
- 实现布局在桌面端与平板端的折叠规则。
- 实现列表页在小屏幕下的退化策略。
- 实现查询区在移动端默认折叠。
- 实现 `DetailDrawer` 在移动端全屏化。
- 预留卡片列表组件。

### 12.3 关键约束

- 不要把桌面端超宽表格原封不动搬到移动端。
- 不要在每个页面里单独写响应式逻辑。
- 响应式能力应统一沉淀在 `responsive` 目录和通用组件中。

### 12.4 验收标准

- 桌面端布局稳定。
- 平板端不会布局错乱。
- 移动端至少可以访问登录、首页、个人入口、基础管理页列表与详情。

### 12.5 Codex 执行提示词

请为第一阶段前端底座补齐响应式基础能力。建立统一断点体系和多端布局规则，使系统在桌面端完整可用、平板端结构合理、移动端关键页面可访问。要求响应式逻辑集中管理，不允许每个页面各自实现一套。对于超宽表格页面，应提供小屏退化策略，而不是硬塞原表格布局。

### 13.2 必做内容

- Redis 启动说明
- 对象存储本地开发方案

### 13.3 验收标准

- 测试账号可以完成主链路验证。

### 13.4 Codex 执行提示词

请为第一阶段补齐运行、联调与部署说明。输出标准环境变量模板、数据库初始化脚本、Redis 和对象存储的本地开发方案、Docker Compose 或统一依赖启动方式，并整理第一阶段主链路自测清单。目标是让新开发者或测试人员无需额外解释即可完成启动和验证。

## 14. 第一阶段主链路验收清单

第一阶段完成后，必须至少人工验证以下链路：

- 输入账号密码登录
- 获取当前用户信息
- 获取可访问租户列表
- 切换租户
- 菜单根据权限变化
- 打开用户管理列表
- 新增用户
- 编辑用户
- 分配角色
- 修改角色菜单
- 重新进入页面后菜单更新
- 查询字典
- 修改配置
- 查看登录日志
- 查看操作日志
- 上传一个文件并查看元数据
- 查看一个任务记录

## 15. 第一阶段代码质量硬约束

- 前端不得直接在页面中散写大量接口请求地址。
- 前端不得跳过统一模板手写特殊布局。
- 前端不得把权限逻辑写成页面私有 if-else。
- 后端不得在控制器中直接操作数据库。
- 后端不得让业务代码自己决定租户过滤方式。
- 后端不得返回不统一的响应结构。
- 后端不得遗漏关键写操作的审计日志。
- 数据库脚本不得手工无版本管理堆叠。
- 任何缓存 key 不得无规范命名。
- 任何关键接口不得没有基础异常处理。

## 16. 第一阶段常见返工点预警

- 不要先写大量页面，再回头抽 `QueryPanel` 和 `DataTable`。
- 不要先把菜单写死在前端，再回头接权限快照。
- 不要先用单租户思路把用户角色写死，再回头补用户租户关系。
- 不要先把导入导出写成同步接口，再回头任务化。
- 不要先只做桌面端页面，完全不考虑响应式。
- 不要忽略 `traceId` 和统一日志上下文。

## 17. 建议的 Codex 执行顺序

如果准备直接交给 Codex 连续编码，建议按以下顺序推进：

1. 搭工程骨架与基础设施。
2. 搭数据库与认证租户闭环。
3. 搭权限快照、动态菜单与主布局。
4. 搭统一页面模板和高频通用组件。
5. 完成用户、角色、菜单、部门四个核心管理模块。
6. 补字典、配置、日志查询模块。
7. 接缓存、文件、任务骨架。
8. 补响应式和运行文档。

## 18. 总控提示词

请按照“大型 SaaS 系统第一阶段底座建设”目标重构并开发本项目。要求以前端 `Ant Design Pro + React 18 + TypeScript`、后端 `Spring Boot 3 + Java 21 + MyBatis Plus + Spring Security` 为基础，优先完成底座能力，不要先堆业务页面。必须严格落地以下能力：统一工程骨架、统一接口响应结构、统一错误码、统一异常处理、认证体系、多租户上下文、RBAC 权限骨架、`permission_key` 统一权限标识、动态菜单、统一主布局、统一列表页/表单页/详情页模板、统一 `QueryPanel/ActionBar/DataTable/DetailDrawer` 组件、用户/角色/菜单/部门/字典/配置/日志最小闭环、Redis 会话与基础缓存、`file_object` 文件元数据骨架、`task_job` 任务骨架、`traceId` 与审计日志、基础响应式能力。所有实现必须可扩展、可维护、符合大型 SaaS 底座思路，不允许通过临时写法绕过统一规范。开发过程中优先保护底座一致性，多租户、权限、日志、缓存和响应式能力必须作为平台级能力实现，而不是散落在具体页面或业务接口中。
