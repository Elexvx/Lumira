# Ant Design Pro 大型 SaaS 系统开发实施路线与第一阶段落地清单

## 1. 文档定位

本规范用于统一大型 SaaS 系统脚手架从方案阶段进入正式开发阶段后的实施顺序、阶段目标、模块优先级、依赖关系、里程碑划分、阶段性交付物与验收标准。

它不是架构补充说明，而是整套平台底座的实施蓝图。

## 2. 实施原则

- 先底座，后业务。
- 先统一，后扩展。
- 先主链路，后增强。
- 先可靠，后丰富。
- 先可运行，后大规模铺开。

## 3. 总体阶段划分

建议分为六个阶段：

1. 脚手架底座建设阶段。
2. 系统管理核心模块建设阶段。
3. 平台运营与租户治理阶段。
4. 异步任务、文件中心与审计增强阶段。
5. 高可用、高并发、监控与运维强化阶段。
6. 业务模块快速复制与平台化扩展阶段。

## 4. 阶段目标总览

### 4.1 第一阶段

完成前端主壳层、后端认证体系、多租户上下文、RBAC 权限骨架、统一接口规范、统一页面模板、统一缓存与会话、基础日志与审计、统一文件上传入口、异步任务骨架和基础部署能力。

### 4.2 第二阶段

完成系统管理基础模块，包括用户、角色、菜单、部门、岗位、字典、配置、租户切换、审计日志查询、登录日志查询等。

### 4.3 第三阶段

完成平台运营与租户治理相关能力，包括租户管理、租户套餐、租户域名、租户配额、租户初始化、租户状态控制、平台级管理视角和平台管理员审计能力。

### 4.4 第四阶段

完成任务中心、导入导出规范化、文件中心元数据化、消息中心基础能力和更多审计增强。

### 4.5 第五阶段

完成高可用增强、限流、降级、熔断、监控、压测、告警、灰度发布、回滚、备份恢复演练等能力。

### 4.6 第六阶段

进入业务模块快速铺设阶段，新增业务模块应主要围绕既有模板和底座能力复制展开。

## 5. 第一阶段定位

第一阶段不是简单做登录页和几个菜单，而是交付一套真正能承载后续开发的基础平台。

第一阶段必须至少做到：

- 前端有统一壳层和统一页面模板。
- 后端有统一认证、租户、权限和请求处理机制。
- 前后端有统一接口规范和统一错误码。
- 缓存、日志、审计、任务、文件留好标准入口。
- 项目能本地启动、测试环境部署、完成基础联调。

## 6. 第一阶段实施顺序

建议严格按以下顺序推进：

1. 完成项目初始化与工程骨架。
2. 完成认证与租户上下文。
3. 完成权限模型与菜单路由联动。
4. 完成前端主布局和统一页面模板。
5. 完成系统管理最小闭环。
6. 补日志、审计、缓存、文件、任务的骨架接入。
7. 完成部署、联调、自测与阶段验收。

## 7. 第一阶段详细工作包

### 7.1 项目初始化与工程骨架

前端侧：

- 完成 `Umi Max + Ant Design Pro + TypeScript` 初始化。
- 建立 `layouts`、`pages`、`components`、`services`、`auth`、`tenant`、`responsive`、`cache`、`hooks`、`types` 等目录。
- 完成全局主题、全局样式、请求封装入口和基础路由结构。

后端侧：

- 完成 `Spring Boot 4.0.6 + Java 21 + MyBatis Plus + Spring Security` 初始化。
- 建立 `common`、`infrastructure`、`modules` 等模块化目录。
- 接入统一异常处理、统一返回结构、统一日志上下文、数据库连接、Redis 连接、基础配置体系和数据库脚本管理工具。

### 7.2 认证体系与租户上下文

需要完成：

- 登录
- 登出
- 刷新 token
- 获取当前用户
- 获取当前租户列表
- 切换租户
- 会话存储
- 租户上下文建立与刷新
- 登录日志记录

前端配合完成：

- 登录页
- 登录状态恢复
- 当前租户信息展示
- 租户切换组件
- 登录失效处理
- 首次进入默认租户处理

### 7.3 RBAC 权限骨架与菜单路由联动

后端完成：

- 角色
- 菜单
- 权限标识
- 用户角色关系
- 菜单树查询
- 权限快照生成
- 接口鉴权注解
- 基础数据范围预留

前端完成：

- 基于权限快照的菜单生成
- 路由裁剪
- 按钮权限组件
- 页面访问控制
- 租户切换后的权限刷新

### 7.4 前端主布局与统一页面模板

需要完成：

- 主布局
- 用户布局
- 空白布局
- 左侧导航
- 顶部工具区
- 标签页
- 页面容器
- 统一列表页模板
- 统一表单页模板
- 统一详情抽屉模板
- 统一查询区组件
- 统一操作栏组件
- 统一表格容器组件
- 统一空态、异常态、加载态组件

### 7.5 系统管理最小闭环

建议优先完成：

- 当前用户信息
- 用户管理
- 角色管理
- 菜单管理
- 部门管理
- 字典管理
- 配置管理
- 登录日志查询
- 操作日志查询

### 7.6 平台能力骨架接入

需要接入：

- 统一文件上传入口和文件元数据表
- 异步任务中心的基础表和查询接口骨架
- 字典和配置缓存
- 操作审计日志
- 统一健康检查和基础监控指标暴露

### 7.7 部署、联调与验收

至少完成：

- Docker Compose 或标准本地运行脚本
- 统一环境变量模板
- 数据库初始化脚本
- Redis 启动方式
- 对象存储本地替代方案
- 前后端联调地址规范
- 测试账号初始化策略

## 12. 第一阶段验收标准

### 12.1 前端验收

- 布局是否统一。
- 页面模板是否统一。
- 菜单是否随权限变化。
- 租户切换是否刷新上下文。
- 按钮权限是否可控。
- 响应式是否基本成立。

### 12.2 后端验收

- 认证是否稳定。
- 租户上下文是否生效。
- 接口鉴权是否统一。
- 日志审计是否能查。
- 缓存是否基本可用。
- 异常返回是否统一。
- 数据库脚本是否规范。

### 12.3 系统链路验收

必须验证以下完整路径：

- 用户登录
- 进入默认租户
- 菜单按权限显示
- 打开用户管理列表
- 新增/编辑用户
- 分配角色
- 修改角色菜单后重新进入页面
- 日志中能看到关键操作记录
- 切换租户后菜单和数据边界变化

## 13. 第二阶段衔接方式

第一阶段完成后，不建议立即大规模铺业务，而应先补齐系统管理细节，把已有模块打磨到足够稳定、足够标准。

第二阶段的本质是对第一阶段骨架做结构验证。

## 14. 推荐开发组织方式

建议按“底座能力包”推进，而不是前后端完全割裂。

推荐能力包：

- 认证与租户能力包
- 权限与菜单能力包
- 统一页面模板能力包
- 系统管理能力包
- 日志与审计能力包
- 文件与任务骨架能力包

## 15. Codex 实施硬约束

- 任何新增页面必须基于统一模板。
- 任何新增接口必须遵循统一响应结构、统一错误码和统一分页结构。
- 任何租户级数据操作必须自动带租户上下文。
- 任何按钮权限必须前后端同时接入。
- 任何导入导出能力不得同步直跑，必须预留任务化路径。
- 任何缓存必须按统一 key 规范实现。
- 任何关键写操作必须记录审计日志。
- 任何页面响应式逻辑必须基于统一断点体系。
- 任何代码提交都不得破坏已完成的主链路闭环。

## 16. 第一阶段常见错误预警

- 过早铺页面。
- 前端先行过头。
- 后端只做接口不做基础设施。
- 把多租户做成表里加 `tenant_id` 就算完成。
- 第一阶段不做部署与运行说明。

## 17. 里程碑定义

建议第一阶段拆成四个里程碑：

1. 工程骨架可运行。
2. 登录与租户闭环打通。
3. 权限与菜单闭环打通。
4. 系统管理最小闭环完成。

## 18. 实施结论

这份实施路线的核心，是把前面所有技术方案从“原则和设计”转化成“明确的开发顺序与交付边界”。

第一阶段必须聚焦底座，不贪多，不乱铺，不跳步骤。只有底座站住，后续平台运营模块、业务模块、高可用增强、异步任务增强和多租户运营能力才能真正顺滑展开。
