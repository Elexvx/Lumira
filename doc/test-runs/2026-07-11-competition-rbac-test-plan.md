# Lumira 赛事报名与角色权限测试计划

## 1. 测试目标

验证赛事后台配置能够准确驱动学生报名表单，普通用户与管理员权限边界有效，角色管理可配置页面访问权限，并回归项目步骤无法进入初赛材料的问题。

## 2. 测试范围

本轮纳入：

- 双账号登录态与菜单差异
- 赛事基础信息、费用、团队人数、成员字段、报名文书和初赛材料配置
- 学生报名向导第 1 至第 5 步
- 动态成员字段新增、填写、删除及双端同步
- Common User 页面路由权限选择能力
- 普通用户直接访问管理路由的 403 拦截
- 前端类型检查及报名流程修复回归

本轮暂不执行：

- 真实支付扣款与第三方支付回调
- 未经确认的正式角色权限保存
- 大文件、恶意文件和高并发专项测试
- 与赛事报名无关的 AI、插件、证书、通知等全量模块

## 3. 测试环境与数据

| 项目 | 内容 |
| --- | --- |
| 环境 | `https://bm.aiadc.org.cn` |
| 普通用户 | John Tao，Codex 内置浏览器 |
| 管理员 | Administrator，独立 Chromium 会话 |
| 赛事 | 全国大学生（AIADC） |
| 普通角色 | Common User |
| 临时字段 | 临时同步测试字段，成员信息、单行文本、可选、启用 |
| 测试项目 | 自动化测试项目 |
| 测试成员 | 测试学生 / 测试大学 / 男 |

## 4. 执行顺序

1. 冒烟确认：两个账号会话、首页、核心菜单和赛事入口。
2. 管理端配置核对：基础信息、费用、人数、字段、文书、材料。
3. 动态字段同步：新增、后台刷新持久化、学生填写、后台删除、学生刷新清理。
4. 权限验证：菜单差异、角色编辑权限树、取消回滚、学生直访管理路由 403。
5. 学生报名正向与逆向：协议、成员、人数、项目必填、材料必填、金额摘要。
6. 缺陷修复回归：项目创建后步骤切换、阶段配置失败降级、错误反馈。
7. 自动化检查：至少执行 `corepack pnpm run typecheck`；按变更影响补充单测。
8. 汇总执行结果、缺陷和发布建议。

## 5. 准入与退出标准

准入：

- 两个账号可登录并保持独立会话。
- “全国大学生”赛事处于已发布状态。
- 管理员具备赛事配置和角色管理权限。

退出：

- 用例文档中的 P0 用例均已有结果。
- 临时字段已删除，角色权限未留下未授权变更。
- 已发现 P0/P1 问题完成修复或明确阻塞原因。
- 类型检查通过；修复回归有浏览器或自动化证据。

## 6. 风险与回滚

- 报名向导自动保存草稿，测试数据可能持久化；报告中需标明测试记录。
- 项目步骤可能在失败前已创建项目或报名，回归前先检查报名列表，避免重复数据。
- 动态字段修改会短暂影响其他报名用户，测试窗口应尽量短，并在验证后立即删除。
- 角色权限只做前端选择和取消验证；如需保存，必须先确认目标角色和目标页面。
- 线上修复需部署后才能做最终回归；本地类型检查不能替代线上验证。
