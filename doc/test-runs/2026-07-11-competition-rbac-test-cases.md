# Lumira 赛事报名与角色权限功能测试用例

## 1. 说明

- 测试环境：`https://bm.aiadc.org.cn`
- 管理员账号：Administrator
- 普通用户账号：John Tao
- 测试对象：赛事“全国大学生”及默认注册角色 Common User
- 状态定义：通过、失败、阻塞、未执行
- 数据原则：新增配置使用“临时同步测试字段”，验证后必须删除；角色权限修改未得到明确要求时不得保存。

## 2. 测试用例

| 编号 | 模块 | 优先级 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- | --- | --- |
| AUTH-01 | 登录与会话 | P0 | 两个独立浏览器会话 | 分别登录普通用户与管理员 | 两个会话互不串号，首页显示对应用户 |
| AUTH-02 | 登录与会话 | P0 | 普通用户已登录 | 刷新报名页面 | 会话保持，不跳转登录页，草稿可恢复 |
| DASH-01 | 首页 | P1 | 普通用户已登录 | 打开工作台 | 显示用户问候、登录记录和普通用户菜单 |
| DASH-02 | 首页 | P1 | 管理员已登录 | 打开工作台 | 显示管理员问候、管理菜单和系统设置入口 |
| RBAC-01 | 菜单权限 | P0 | 双账号已登录 | 比较两端一级菜单 | 管理员菜单明显多于普通用户；普通用户无用户中心、数据管理等菜单 |
| RBAC-02 | 路由权限 | P0 | 普通用户已登录 | 直接访问 `/user-center/roles` | 跳转 `/403`，显示无权限提示 |
| RBAC-03 | 角色管理 | P0 | 管理员已登录 | 打开角色管理 | 列表显示角色编码、类型、默认页、权限数和用户数 |
| RBAC-04 | 角色管理 | P0 | 打开 Common User 编辑窗口 | 展开页面路由权限并执行全选 | 控件可切换，按钮由“全选”变为“全不选” |
| RBAC-05 | 角色管理 | P0 | 已临时修改权限选择 | 点击取消并重新打开角色 | 未保存的权限变更不应落库 |
| RBAC-06 | 角色管理 | P1 | 管理员已登录 | 检查页面动作权限区域 | 页面未授权时按钮权限不生效；授权页可查看对应动作权限 |
| COMP-01 | 赛事列表 | P0 | 管理员已登录 | 打开赛事管理 | “全国大学生”可见且状态为已发布 |
| COMP-02 | 基础配置 | P0 | 打开赛事配置 | 核对名称、类别、级别、参赛范围 | 学生端可选赛事及描述与后台一致 |
| COMP-03 | 费用配置 | P0 | 打开赛事基础信息 | 核对收费方式、金额、货币 | 按人数收费，50.00 CNY；学生端应付费用计算口径一致 |
| COMP-04 | 团队限制 | P0 | 打开报名设置 | 核对最小和最大团队人数 | 最少 1 人、最多 20 人，学生端按钮计数和校验一致 |
| COMP-05 | 成员字段 | P0 | 打开报名设置 | 核对字段名称、标识、必填、启用和排序 | 姓名、学校、性别均启用且必填，学生端顺序一致 |
| COMP-06 | 报名文书 | P0 | 打开报名须知与文书 | 核对标题、正文、阅读时间、启用状态 | 承诺书与知情同意内容在学生端一致展示 |
| COMP-07 | 初赛材料 | P0 | 打开赛程与材料 | 核对材料名称、阶段、格式、大小和必填状态 | 学生端初赛材料要求为作品文件、不限格式、10 MB、必填 |
| FIELD-01 | 动态字段 | P0 | 管理员打开报名字段配置 | 新增启用的可选成员字段“临时同步测试字段” | 后台自动保存，刷新后字段仍存在 |
| FIELD-02 | 动态字段 | P0 | FIELD-01 完成 | 普通用户刷新团队步骤 | 表头和编辑输入框出现新字段 |
| FIELD-03 | 动态字段 | P0 | 新字段已显示 | 填写“同步成功”并保存成员 | 列表正确显示新字段值，原字段不丢失 |
| FIELD-04 | 动态字段 | P0 | FIELD-03 完成 | 管理员删除临时字段，普通用户刷新 | 新字段同步消失，姓名、学校、性别及原值保留 |
| REG-01 | 报名入口 | P0 | 普通用户已登录 | 打开赛事报名列表 | 列表、筛选和“新增报名”入口正常 |
| REG-02 | 选择赛事 | P0 | 进入报名向导 | 展开赛事选择 | 只展示已发布且可报名赛事；“全国大学生”可选 |
| REG-03 | 文书确认 | P0 | 已选择赛事 | 未确认协议观察下一步，再依次确认 | 未确认时按钮禁用；全部确认后按钮启用 |
| REG-04 | 创建团队 | P0 | 已进入团队步骤 | 填写团队信息并新增成员 | 成员字段与后台配置一致，成员可保存 |
| REG-05 | 团队人数下限 | P0 | 团队最小人数为 1 | 不添加成员直接下一步 | 阻止继续并提示至少需要 1 位成员 |
| REG-06 | 项目必填 | P0 | 进入项目步骤 | 项目名称留空点击下一步 | 阻止继续并提示“请输入项目名称” |
| REG-07 | 创建项目 | P0 | 项目字段合法 | 填写项目名称和简介后下一步 | 项目和报名记录创建成功，进入初赛材料步骤 |
| REG-08 | 阶段配置降级 | P0 | 阶段表单接口失败或无配置 | 完成项目步骤 | 已创建报名不应卡在项目页；进入材料步骤并显示可理解的空态或提示 |
| REG-09 | 材料必填 | P0 | 初赛材料配置为必填 | 不上传作品文件直接下一步 | 阻止继续并提示作品文件必填 |
| REG-10 | 材料限制 | P1 | 初赛材料页可用 | 上传超过 10 MB 或不符合限制的文件 | 拒绝上传并显示明确原因 |
| REG-11 | 支付金额 | P0 | 1 名成员且每人 50 CNY | 到达确认支付步骤 | 应付金额为 50.00 CNY，赛事、团队、项目摘要正确 |
| REG-12 | 最终提交 | P0 | 所有必填项完成 | 在得到确认后提交/支付前最后检查 | 不重复创建报名；状态、报名编号和列表记录一致 |
| ERR-01 | 异常反馈 | P0 | 任一业务接口失败 | 执行对应操作 | 加载状态结束，页面显示明确错误，不应静默停留 |
| DATA-01 | 草稿恢复 | P1 | 报名向导已有草稿 | 刷新或重新进入向导 | 当前步骤、团队、成员和项目字段可恢复 |
| DATA-02 | 测试清理 | P0 | 动态字段测试完成 | 删除临时字段并刷新两端 | 正式赛事配置无测试字段残留 |

## 3. 通过标准

- P0 用例全部执行；未通过项必须有缺陷编号、复现步骤和影响说明。
- 动态字段测试完成后无临时配置残留。
- 角色权限测试默认仅验证选择能力并取消，不改变 Common User 正式权限。
- 最终报名提交、支付或真实权限保存属于有外部影响的操作，执行前单独确认。
