# Lumira 回滚方案

本文用于发布失败或高风险功能异常时快速止损。执行生产回滚前，必须先保存故障现场、确认最近一次可恢复备份，并指定操作人与复核人。

## 代码回滚

- 回滚到上一个稳定 commit。
- 后端和前端镜像 tag 回退到上一个生产稳定 tag。
- 禁止用本地未验证镜像直接覆盖生产。

## 配置回滚

- 恢复上一稳定版本环境变量。
- CORS、JWT、字段加密、插件签名和内部 job token 不允许回退成弱配置。
- Swagger UI、api-docs、actuator 和 observability 端口继续保持生产保护策略。

## 数据库回滚

- 本轮安全收尾相关 migration 以新增表、字段和索引为主，默认不删除旧数据。
- 不可逆 migration 包括字段结构收缩、数据清洗、密钥轮换、状态迁移和历史记录合并；执行前必须确认备份可恢复。
- 新增表可保留，新增字段可保留；代码回滚后未使用字段不得手工删除。
- 如必须恢复，按发布前全量备份恢复到隔离库，校验后再执行生产恢复。

## 文件存储回滚

- 已上传文件不删除。
- 校验 `file_object` 记录、对象 key、本地/对象存储文件存在性和下载权限一致。
- 如文件处理任务回滚，保留 `file_processing_task` 和 artifact，待修复后重放。

## AI 工具回滚

- 立即禁用高风险工具开关。
- 禁用数字员工执行写工具，仅保留只读工具。
- 保留 AI 工具拒绝、确认和审批审计，供事后复盘。

## 支付 Webhook 回滚

- 降级为只记录不处理，暂停订单状态推进。
- 保留 provider event id 和幂等键，防止恢复后重复处理。
- 签名失败和租户解析失败继续拒绝，不允许回退到信任 `X-Tenant-Id`。

## 验证步骤

- `/api/health`
- 登录成功。
- `current-user` 成功。
- 文件中心列表、上传和下载。
- 支付 webhook invalid signature 拒绝，合法测试事件幂等。
- AI chat 和只读工具可用，高风险工具被拒绝或要求确认/审批。
