# Lumira 产品需求文档（PRD）

本文定义 Lumira 的产品范围、目标用户、核心流程、功能优先级和验收口径。技术实现不在本文重复描述；开发时同时遵循 [文档导航](README.md) 中对应的架构与开发规范。

## 1. 产品概述

Lumira 是面向企业管理场景的 SaaS 平台底座。它把认证、权限、配置、文件、消息、插件、国际化、支付、AI 和运维能力组合成可复用平台，让新业务可以在统一的租户、安全和审计体系上快速落地。

当前版本的目标不是覆盖 CRM、ERP 或 OA 等完整垂直业务，而是形成以下闭环：

- 用户可以登录、恢复会话并访问获授权的页面。
- 管理员可以管理用户、组织、角色、菜单、配置和审计。
- 业务用户可以使用文件、消息、AI 助手和下载中心。
- 平台可以通过插件、国际化、支付和后台任务继续扩展。
- 运维人员可以部署、监控、备份、恢复和回滚。

## 2. 成功标准

| 目标 | 可验证结果 |
| --- | --- |
| 可用 | 登录、工作台、用户权限、文件、消息和 AI 主链路可完成 |
| 安全 | 后端执行认证、租户、操作和数据范围校验；高风险操作可审计 |
| 可配置 | 品牌、安全、验证、通知、支付和资料字段可由管理员维护 |
| 可扩展 | 新模块可通过稳定 API、事件和插件能力接入，不穿透其他模块数据 |
| 可运维 | 支持健康检查、日志与指标、容器部署、备份恢复和回滚 |

## 3. 用户与权限边界

| 角色 | 主要任务 | 典型权限范围 |
| --- | --- | --- |
| 平台超级管理员 | 初始化与治理整个平台 | 全局配置、用户角色、插件、支付、AI、监控和审计 |
| 租户/组织管理员 | 管理本组织人员与基础配置 | 用户、角色、部门、字典、文件和租户级设置 |
| AI 管理员 | 管理模型、员工、知识库和工具策略 | AI 配置、知识库、工具与 AI 审计 |
| 插件管理员 | 管理插件生命周期与安全 | 上传、安装、升级、回滚、启停、卸载和日志 |
| 运维人员 | 部署、监控与恢复 | 健康检查、日志、观测、备份和回滚 |
| 普通业务用户 | 使用获授权的平台能力 | 工作台、个人中心、文件、消息、下载和 AI 助手 |

前端只负责展示裁剪和访问引导；后端是认证、授权、租户隔离和数据范围的最终边界。详细模型见 [权限与多租户规范](05-permission-rbac.md)。

## 4. 核心流程

### 4.1 登录与访问

1. 登录页读取当前可用的账号密码、验证码、微信或 Passkey 等能力。
2. 用户完成身份校验，系统签发访问令牌、刷新令牌和会话。
3. 前端读取当前用户、角色、菜单和权限快照。
4. 系统进入默认首页；无权限页面进入 403，不存在页面进入 404。

### 4.2 用户与权限管理

1. 管理员维护部门、用户、角色和菜单。
2. 管理员为角色配置菜单、操作权限、数据范围和默认首页。
3. 管理员为用户分配部门和角色。
4. 授权变化使权限快照失效；用户刷新后获得新权限。
5. 关键写操作进入审计日志。

### 4.3 AI 助手与知识库

1. AI 管理员配置模型服务、AI 员工、知识库和工具策略。
2. 管理员上传文档并完成解析、索引或重建。
3. 用户发起普通或流式对话，系统可返回知识引用和工具调用提议。
4. 高风险工具需要确认或审批；调用结果和拒绝原因可追踪。
5. 用户可以管理、导出或分享会话。

### 4.4 文件与消息

1. 用户上传文件，系统校验权限、安全属性并保存元数据。
2. 用户按权限预览、下载或删除；管理员维护存储空间。
3. 业务或管理员创建站内消息，用户查看未读数并标记已读。
4. WebSocket 用于实时通知，失败投递通过 Outbox 重试。

### 4.5 插件与内容治理

1. 管理员上传插件包，系统校验定义、版本、权限和安全策略。
2. 管理员安装、升级、回滚、启用、停用或卸载插件。
3. 获授权用户从统一插件容器访问插件能力。
4. 敏感词等治理插件可以维护词库并拦截命中内容。

### 4.6 部署与恢复

1. 前端部署到 Vercel 或自托管站点，通过 `/api` 和 `/ws` 访问后端。
2. 后端通过 Docker Compose 启动同步入口、异步运行时、调度器、代理与基础设施。
3. 部署后执行健康检查和轻量冒烟。
4. 重要变更前备份；故障时按回滚方案恢复代码、配置和数据。

## 5. 功能范围与优先级

优先级含义：P0 是平台可用的必要条件；P1 是正式交付应具备的增强能力；P2 是按业务接入进度启用的扩展能力。

### 5.1 认证与导航

| 优先级 | 能力 |
| --- | --- |
| P0 | 账号密码登录、登录保护、Token 刷新、登出、当前用户、动态菜单、路由访问控制 |
| P1 | 短信/邮箱验证、二次验证、Passkey、微信登录、响应式导航和顶部操作区 |

### 5.2 用户、组织与权限

| 优先级 | 能力 |
| --- | --- |
| P0 | 用户查询/新增/编辑/状态、部门树、角色维护、菜单权限、权限树、个人资料 |
| P1 | 用户删除、在线会话、默认注册角色和数据范围配置 |

### 5.3 平台配置

| 优先级 | 能力 |
| --- | --- |
| P0 | 字典、安全策略和基础系统配置 |
| P1 | 品牌与主题、资料字段、协议、水印、验证渠道、通知渠道、支付配置和 API 文档入口 |
| P2 | 平台更新检查 |

### 5.4 AI

| 优先级 | 能力 |
| --- | --- |
| P0 | AI 助手、流式对话、会话管理、AI 员工、模型服务、知识库与文档索引 |
| P1 | 工具注册/确认/执行、工具策略、治理概览、会话导出和公开分享 |

### 5.5 文件与消息

| 优先级 | 能力 |
| --- | --- |
| P0 | 文件列表/上传/下载，消息列表/已读/未读数 |
| P1 | 文件预览/删除、存储空间、下载中心、WebSocket、消息归档和投递日志 |

### 5.6 插件、国际化与支付

| 优先级 | 能力 |
| --- | --- |
| P0 | 插件定义、上传、校验、安装、升级、回滚、启停和卸载 |
| P1 | 插件安全与日志、插件运行时、敏感词治理、语言/命名空间/词条、发布与回滚、支付服务商配置 |
| P2 | 支付订单、退款、Webhook 和支付事件 Outbox |

### 5.7 审计与运维

| 优先级 | 能力 |
| --- | --- |
| P0 | 登录/操作审计、服务健康、后端容器部署、环境检查和部署自检 |
| P1 | AI/验证日志、Redis 状态、备份恢复、轻量压测和资源保护 |
| P2 | Prometheus、Grafana、Loki、Tempo 与 OpenTelemetry 完整观测栈 |

## 6. 页面范围

页面事实以 `lumira-ui/src/routes/meta.ts` 为准。产品验收覆盖以下页面组，不在 PRD 中复制完整路由表：

- 登录、403、404。
- 工作台和下载中心。
- 用户、部门、角色、在线用户和个人中心。
- 菜单、字典、资料字段、个性化、安全、验证、通知和支付设置。
- AI 助手、知识库、AI 员工和会话分享。
- 我的文件、全部文件和存储空间。
- 消息入口、插件管理、插件运行时、敏感词和国际化。
- 审计、系统监控、API 文档和平台更新。

逐页操作与期望结果见 [手工测试工作簿](24-page-manual-test-workbook.md)。

## 7. 数据与接口约束

- 租户级数据必须由后端强制隔离，不能只依赖前端传入的 `tenantId`。
- 敏感配置加密存储或脱敏展示；密码、Token 和密钥不得进入日志。
- 高风险写操作记录 actor、tenant、resource、result 和 requestId。
- 增长型文件、消息、日志和任务数据需要归档与清理策略。
- 普通 API 使用统一响应和业务错误结构；文件与流式接口可以例外，但仍需鉴权与错误处理。
- 分页接口限制最大 `pageSize`；写接口执行服务端校验和必要的幂等保护。
- 具体字段、状态码和路径以 [接口规范](04-interface-spec.md) 和代码中的 Controller/DTO 为准，PRD 不维护重复接口清单。
- 表结构、迁移和 owner 规则见 [数据库规范](03-database-design.md) 与 [数据归属](13-service-data-ownership.md)。

## 8. 非功能需求

### 安全

- 所有管理接口执行后端鉴权和租户边界校验。
- 支持登录保护、验证码、二次验证和 Passkey 等增强认证。
- 插件和 AI 工具受权限、确认/审批和审计约束。
- 生产环境使用强密钥和明确 CORS 来源，只对公网开放必要端口。

### 可用性与性能

- 健康检查可供部署脚本和外部监控探测。
- 主链路失败时返回用户可理解的提示和可定位的 requestId。
- API 入口、登录和验证码具有限流保护。
- 分页、连接池、线程池、Redis 内存和 Docker 日志具有上限。

### 可维护性与可扩展性

- 模块必须明确代码、表、API、权限和事件 owner。
- 数据库变更通过正式迁移或初始化脚本管理。
- 跨模块访问使用契约、Internal API、事件或读模型。
- 当前保持模块化单体；只有边界稳定且有独立扩缩容/发布需求时才物理拆分。

### 可观测与恢复

- 提供健康、版本、指标、日志和 Trace 能力。
- 登录、操作、AI 和验证行为可按权限查询审计记录。
- 发布前可以备份数据库、Redis、上传文件、插件文件和环境配置。
- 回滚过程可验证登录、权限、文件、AI 和支付等关键链路。

## 9. 验收标准

### 9.1 产品主链路

| 验收项 | 通过条件 |
| --- | --- |
| 登录与会话 | 可登录、恢复、刷新和登出；失败提示明确 |
| 权限与租户 | 不同角色只看到获授权菜单；越权接口被后端拒绝；租户数据隔离 |
| 用户与组织 | 管理员可维护用户、部门、角色、菜单和数据范围 |
| AI | 可完成对话、流式响应、会话管理、知识库索引和受控工具调用 |
| 文件与消息 | 可上传/下载文件、查询消息、标记已读并获取实时通知配置 |
| 平台扩展 | 插件生命周期、国际化发布/回滚和支付配置可操作 |
| 审计与运维 | 关键操作可追踪，健康检查、备份和部署自检可执行 |

### 9.2 工程质量

从仓库根目录执行：

```bash
./lumira-backend/mvnw -f lumira-backend/pom.xml \
  -pl services/lumira-admin -am test
corepack pnpm --dir lumira-ui typecheck
corepack pnpm --dir lumira-ui test
corepack pnpm --dir lumira-ui build
node bin/check-deployment.mjs
git diff --check
```

测试范围、缺陷等级和准出条件见 [测试策略与用例](21-test-strategy-and-cases.md)。正式发布需要 P0、P1 缺陷为 0，核心主链路与冒烟用例通过率为 100%。

## 10. 明确不在当前重点范围

- 完整 CRM、ERP、OA 等垂直产品。
- 大规模租户计费、套餐售卖和商业化运营闭环。
- 通用低代码搭建和复杂工作流平台。
- 原生移动 App。
- 多地域容灾、跨云部署和超大规模分库分表。
- 所有支付渠道与 AI 供应商的完整适配矩阵。

新增上述范围前，必须先补充业务目标、用户流程、优先级、数据 owner、非功能指标和验收用例，不能直接把技术实现当作需求。

## 11. 风险

| 风险 | 控制方式 |
| --- | --- |
| 模块化单体继续膨胀 | 用 owner、契约和架构测试保护边界，满足拆分条件后再物理拆分 |
| 外部 AI 服务不可用 | 连通性检查、明确错误、可观测状态和本地/备用 Provider 降级 |
| 插件或 AI 工具越权 | 权限声明、运行策略、确认/审批、owner API 和审计 |
| 小型服务器资源不足 | 限流、资源上限、日志轮转和部署后压测 |
| 密钥泄漏 | `.env` 不入库、强密钥、字段加密、展示脱敏和定期轮换 |
| 权限配置错误 | 权限树、默认角色、快照失效、后端校验和回归用例 |
